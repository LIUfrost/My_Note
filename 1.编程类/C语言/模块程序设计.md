## 程序封装
==在公开的API边界上，优先使用句柄(或抽象接口)；==
==在模块内部实现中，可以自由使用具体类型==
### 句柄(不透明指针)
```C
//vec.h
typedef struct Vec Vec;
size_t vec_size(const Vec* V);
```
>将指针的具体结构封装到vec.c源文件中，而不是放在vec.h中
>[好处]
>· 调用方只能通过vec_size()来使用结构体，而不能知道其具体结构
>· 修改Vec结构体内部实现时，不影响头文件
>· 可以在不改变接口的情况下优化内部实现
### 前向声明
>[本质]：在源文件中定义结构体内部，在头文件中只声明。
```C
//vec.c - 源文件(隐藏实现)
struct Vec{
	void* data;
	size_t length;
	size_t capacing;
	//可以随时添加新字段而不影响外部
}
//vec.h - 头文件
struct Vec;
typedef struct Vec Vec; //都可以
```
>[注意]：前向声明的类型是不完全类型
>当编译器需要知道**结构体大小**时，必须要有完整的定义！
```C
typedef struct Vec Vec;
void func(){
	Vec v;  //X错误：编译器不知道要分配多少内存
	Vec *p; //V正确：指针大小是固定的(4字节或8字节)
	p->len; //X错误：编译器不知道结构体有哪些成员	
}
```
### 回调
==一段可执行代码(通常是函数和方法)作为参数传递给另一个函数或模块==
==以便在将来某个时刻被调用==

`为什么要用回调？`
- 实现异步处理
- 提高灵活性
- 事件驱动编程
- 解耦调用者与被调用者，增强灵活性
```C
#include<stdio.h>
//定义一个函数指针类型EventHandler,可以指向一个返回void，接受一个int参数的函数
typedef void(*EventHandler)(int eventCode);
// 一个函数，接受回调作为参数
void simulateEvent(EventHandler callback) {
    printf("模拟事件发生...\n");
    callback(42); // 调用回调，传入事件码
}
// 实际的事件处理函数(符合EventHandler模板)
void myHandler(int code) {
    printf("事件处理：收到代码 %d\n", code);
}
// 在main中调用simulateEvent(Handler)
int main() {
    simulateEvent(myHandler); // 传递回调
    return 0;
}
>>>模拟事件发生...
>>>事件处理：收到代码 42
```
>[好处]：
>simulateEvent只负责“触发事件”，不关心具体怎么处理
>可以随时换处理函数而不需要修改simulateEvent
## 头文件设计与使用规范
`若把所有的结构体细节都放到.h,会发生什么？`
- 封闭性破坏
- 编译依赖爆炸，构建变慢
- 兼容性丧失
- 安全风险
>[注意]修改头文件结构体会导致重新编译
>预处理机制：#include是文本替换，头文件内容会被”复制“到每个包含他的.c文件中
>依赖传播：如果vec.h被a.c,b.c,c.c包含，修改vec.h会导致这3个文件都需要重新编译
### 头文件推荐组织
Project/
	include/     # 只放稳定接口
		vec.h   # 对外API
		logger.h
	src/             # 实现
		vec.c
		logger.c
		internal/
			vec_impl.h # 私有头(仅src内部使用)
	tests/           # 测试/示例
		test_vec.c
### 头文件模板
```C
//vec.h(公共接口)
#ifndef VEC_H         // 头文件保护
#define VEC_H
#include<stddef.h>    // 只include自己真正需要的
typedef struct Vec Vec; // 不透明指针：隐藏实现细节
Vec* vec_create(void);
void vec_destroy(Vec *v);
int vec_push(Vec*v,int x); // 返回错误码
size_t vec_size(const Vec*v);
#endif // VEC_H
```
>[#ifndef/#define]：包含保护，防止头文件被重复包含导致重复定义
### 头文件要求
#### ==**1.自洽**==
- 独自被#include时能够编译通过，不依赖其他头文件被提前包含
- 显式地包含了直接使用的所有类型，宏，函数的声明
```C
// 反例 - vec.h
void vec_add(Vector *v,size_t n); // 使用了size_t，但没有包含<stddef.h>
// 若某个.C文件
#include"vec.h"   // 编译错误！size_t未定义
// 必须改为
#include<stddef.h>
#include"vec.h"   // 正确，但依赖包含顺序
// 必须先包含A才能包含B的依赖就是不自洽
```
#### ==**2.依赖最小化**==
- 采用前向声明，只声明类型名，不包含完整定义
- 减少依赖，只用指针时不需要#include
#### ==**3.禁止循环包含**==
- **定义**:头文件A直接或间接的包含了头文件B，而头文件B又直接或间接的包含了头文件A
- **导致**:编译错误，设计耦合，难以维护
```C
//a.h
#ifndef A_H
#define A_H
#include "b.h
typedef struct A {B*b;}A;
#endif
//b.h
#ifndef B_H
#define B_H
#include "a.h"
typedef struct B {A*a;}B;
#endif
```
>虽然头文件保护**防止了无限递归包含**，但**类型定义顺序**导致了问题：
>// 最终预处理后的代码顺序
>typedef struct B { A* a; } B;  // 错误：类型 A 在此处尚未定义
>typedef struct A { B* b; } A;  // B 已经定义，所以这里没问题
>**错误：** 在定义 `struct B` 时，`A` 类型还未声明，导致编译错误。
- **如何避免**:使用前向声明代替包含；将互相依赖的类型放到同一个头文件中；使用#pragma once
>[pragma once]：不能解决设计上的循环，但可以防止同一文件多次包含，配合前向声明使用更简洁
#### ==**#pragma once**==
- **工作原理**：预处理器处理到#pragma once时， 它会记录当前文件的唯一标识。 当后续再次遇到#include指向同一个文件时， 预处理器会检查该文件是否已经在列表中：
- 如果已经在列表中， 则完全跳过该文件的内容
- 如果不在列表， 则正常展开文件内容， 并将其加入列表
```c
// a.h
#pragma once
#include "b.h"
typedef struct A { B* b; } A;

// b.h
#pragma once
#include "a.h"
typedef struct B { A* a; } B; 
```
>但**类型定义顺序**还是导致了问题：
>// 最终预处理后的代码顺序
>typedef struct B { A* a; } B;  // 错误：类型 A 在此处尚未定义
>typedef struct A { B* b; } A;  // B 已经定义，所以这里没问题
>**错误：** 在定义 `struct B` 时，`A` 类型还未声明，导致编译错误。
- **正确解决办法**
```C
// a.h
#pragma once
struct B; // 前置声明， 告诉编译器 B 是一个结构体类型
typedef struct A { struct B* b; } A; // 使用 struct B*（B 尚不完整， 但指针允许）
#include "b.h" // 如果需要使用 B 的完整定义， 可以放在这里， 但通常可以省略

// b.h
#pragma once
struct A; // 前置声明
typedef struct B { struct A* a; } B;
```
#### ==**4.避免变量定义**==
- **除非static const或extern声明**
- **static变量**具有内部链接， 即只在定义它的编译单元（ 当前 .c 文件及其直接或间接包含的头文件） 内可见
- **extern**声明变量而不定义， 告诉编译器变量在别处定义
```C
// counter.h
extern int g_count; // 只是声明， 不分配内存

// counter.c
int g_count = 0;    // 真正的定义， 分配内存
```
#### ==**5.避免函数实现**==
- **当头文件被多个 .c 文件包含时， 导致多重定义**
- **导致的问题**：编译时间增加；代码膨胀；破坏封装
```C
//util.h                        //编译过程
int add(int a, int b) {         //# 编译 main.c
	return a + b;               //gcc -c main.c → main.o
}                               //main.o 包含 add 的定义
                                //# 编译 test.c
//main.c                        //gcc -c test .c → test .o
#include "util.h"               //test .o 也包含 add 的定义
int main() { return add(1,2); } //# 链接
                                //gcc main.o test .o -o app
//test.c                        //错误！ 链接器发现 add 被定义了2次
#include "util.h"               //→ multiple definition of 'add'
void test () { add(3,4); }
```
- **解决方法**：
- 避免不通模块的函数名冲突（ C语言没有命名空间）
- 同一模块的所有函数用统一前缀（ 如 vec_\*、 logger_\*）
